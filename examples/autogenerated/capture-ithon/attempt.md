# Checked Ithon capture migration

The user explicitly requested Ithon for the existing Python capture implementation. Extend that implementation and the existing shared movie route; do not introduce another encoder or group engine.

Domains: source images, ordered events, admitted finite permutations, declared source identities, a private candidate movie, a verified public movie, and the inherited shared pipeline's independent result. `validate_manifest : object → tuple[int,int,int,list[str]]` admits the foreign JSON boundary. `export : path × path × path → path` is an effectful compatibility operation. `generate : path × path × path × path → path` delegates actual mathematical production to the pinned shared FP operation. Kitchen alone owns encoding.

Invariants: exactly one image per point, no Boolean points/frames masquerading as integers, ordered bounded events, exact image sequence and digests, strict decoding and decoded count, exact clean Kitchen source, and preservation of prior public output after failure. Shared generation refuses a wrong FP source or reused output before effects. Imports must be checked by Ithon, with their executed source hashes retained.

Runtime: actual Ithon host frontend 74ab6d6044b07b76a910978437a34a6b5ac6acda. All owned source and tests use typed .pi, assignment arrows and return signatures. Its foreign host/runtime files and FP's existing legacy controller remain explicitly inherited boundaries; no new maintained Python source or extension-only rename is used.

Migration errors exposed missing explicit imports, unknown foreign-call return types, unsupported bytes/string repetition, and foreign-object indexing. The final source uses explicit typed admission values and simple loops rather than an unchecked fallback. These are bounded source-adaptation findings, not a claim that the compiler is broken. Possible next language work: typed signatures for common foreign APIs, type-guard narrowing and typed sequence repetition, accepted only with positive and invalid-type tests.

The real corrupt-image case exposed a product defect: FFmpeg recovery could conceal a broken compressed PNG. Strict decoding plus a source decoded-frame count now rejects it before encoding. The migrated suite runs all media cases, requires a real pinned Kitchen checkout, preserves old output after each refusal and verifies the actual imported export.pi receipt.
